# 连接器与本机服务

Task Out 将读取格式、连接位置和客户端身份分开。连接器负责格式，连接配置决定读取范围，明确的来源标记或用户确认决定显示身份。新工具使用已有格式时可以直接配置；新格式需要增加连接器，或先导入标准记录。

## 首版连接器

| 连接器 ID | 候选位置 | 已实现能力 | 边界 |
|---|---|---|---|
| `codex-rollout` | 当前用户的 Codex `sessions`、`archived_sessions` | 历史、增量、稳定身份、原始创建时间、父子关系、最近活动、可选名称资料读取 | 先以有界头部验证格式，只使用与文件名身份匹配的 metadata；名称资料目录单独选择 |
| `claude-jsonl` | 当前用户的 Claude 兼容 `projects` 存储 | 历史、增量、近况、客户端线索、新旧子代理文件结构、`custom-title` 名称 | SDK 入口不能唯一识别应用；没有显式创建时间时保留未知 |

两种连接器均不修改源日志，不宣称能实时监测运行或直达原会话。详情提供定位信息与最近消息，状态显示未知。父子关系可信时，子代理在父会话详情中展示。

发现只检查候选目录和实际名称文件的位置，不读取会话正文或名称文件内容、不自动启用。默认候选使用当前用户主目录，可通过 `CODEX_HOME`、`CLAUDE_CONFIG_DIR` 或连接表单中的绝对路径覆盖；没有安装某个工具不影响其他功能。候选按真实目录去重，附带普通显示名称、图标、目录依据与可用名称位置；无法访问和未找到分别通过 `diagnostics` 给出处理动作。格式和客户端身份在选择范围并预览后确认，SDK 入口显示“Claude SDK（客户端未知）”。

扩展提供“启动 → 配对 → 发现 → 预览 → 启用”引导，可保存步骤与非敏感配置草稿，关闭后继续；配对码不保存。目录和格式等技术配置位于高级设置，但预览前始终展示实际读取范围。点击预览才读取所选日志和名称资料，不调用模型、不保存连接或游标。格式不支持时不能直接保存或通过编辑连接绕过校验；当前时间窗无记录或有效空目录允许启用等待后续活动。

## 配置与同步

| 配置 | 默认值或作用 |
|---|---|
| `connectorId` | 从已提供的连接器中选择 |
| `name`、`root` | 自定义连接名称与绝对数据目录；不据此创建项目 |
| `historyDays` | 仅 `3`、`7`、`30`，默认 `30`；按来源提供的最近活动时间滚动计算，包含窗口起点，排除未来时间及活动时间未知的记录 |
| `pollIntervalMs` | 新连接默认 `60000`；`0` 为本机连接仅手动读取，其余为 5000～86400000 毫秒的整数。已有自定义值保留 |
| `enabled` | 是否进行后续采集；暂停保留缓存 |
| `allowAI` | 默认 `false`，允许标题参与模型整理 |
| `includeSummary` | 默认 `false`，需同时开启 `allowAI` 才允许发送近况 |
| `includeNaming` | 默认 `false`，需同时开启 `allowAI`；仅为缺名会话发送首条有效用户消息和最新有效消息节选，各最多 1200 字符 |
| `metadataRoot` | Codex 可选名称资料目录，默认空；显式选择后才读取目录内的 `session_index.jsonl` 与兼容 `state_*.sqlite`，不由日志目录权限自动推导 |
| `identity` | 可选的 `{id,label,icon}`，表示用户确认整个连接属于该客户端；混合目录保留自动识别 |
| `storageId` | 可选的稳定存储身份，用于开发集成或明确的目录迁移；不改变会话原始 ID |

仅调整图标或颜色时，使用扩展设置中的“图标与颜色”，无需填写 `identity` 或改变连接。外观覆盖按 `source.id` 保存在扩展本地，同一来源的不同连接共用该外观；不同来源即使使用相同图标也可设置不同颜色。连接器继续提供原始名称、图标与识别依据，不参与用户外观的保存。

扩展另有「设置 → 会话与进展刷新频率」：默认 60 秒，可选 0 / 30 / 60 / 120 / 300 秒，0 表示扩展只手动刷新会话进展，网页自动整理仍正常工作。该设置控制扩展拉取与已归类会话的进展更新频率；本机连接的 `pollIntervalMs` 独立控制目录读取，不因扩展选择仅手动刷新而自动停服。定时同步尊重连接的到期时间，手动刷新可主动读取。刷新只是检查是否有变化，没有获准输入变化时不调用模型。

新会话首次自动归类后，后续模型请求只可更新获准的一句近况，不能重分组、改主要类型或改固定名称。「重新整理当前内容」是显式重新归类入口，仍保护人工修改和已固定名称；「刷新进展」只更新近况。

表单先测试再启用。预览统计本次可读取范围内的主会话、子会话及总数，按稳定身份去重；最多展示 10 条，主会话优先。`sampleLimited` 表示样例未全显示，`truncated` / `scanTruncated` 表示扫描预算导致读取未完整，`partial` 表示存在读取警告；后两种情况下数量只能说明已读到的部分。启用后自动增量同步，也可主动刷新。时间窗口持续滚动：最近活动早于窗口的未归档记录从当前内容和稍后查看隐藏，归档仍保留。收窄范围不删除本地缓存、固定名称、项目、标签或其他人工整理；扩大到 7 或 30 天后，重新处于窗口内的记录恢复显示。窗口用于本地会话连接，不筛除打开的浏览器页签。

源记录的最近活动时间必须有效且不晚于当前时间；创建时间未知但最近活动可信的记录仍可收录，不使用文件修改、复制或同步时间代替。旧版保存的 `historyDays: 0`（全部历史）升级为 `30`，不再提供全部历史选项。新配置只接受 3、7、30。

同目录重复添加会返回冲突；同一存储的重叠范围、活动目录与归档目录共享稳定身份，记录合并多个连接观测。获取窗口按连接范围的并集计算，模型权限仍采用更严格限制。暂停或来源离线保留缓存，已有记录仍受原时间窗口约束。移除连接只断开采集，保留已收录记录，不会让缓存获得新的模型发送许可。

游标按字节记录，完整换行后才解析，UTF-8 尾部和半行留到下次。坏行产生警告并继续其他行；截断、替换和移动重新检查身份。来源离线保留缓存与最后成功同步时间。目录中的符号链接被跳过，已授权根目录被重定向时停止读取，实际路径必须在保存的授权范围内。

首版每次扫描最多 10000 个文件、最多 16 层；单文件一轮最多读取 64 MB，后续同步继续；单行上限 8 MB。图片等超长行会被跳过并显示警告，后面的有效消息继续读取；跨同步批次仅保存跳过状态，不缓存超长正文。Codex 首行 metadata 预检上限 1 MB，格式未识别时不缓存正文。近期消息缓存最多 60 条，不构成完整历史备份。大历史库应缩小配置范围，首版尚无大规模性能保证。

## 会话名称与命名依据

显示顺序为：**Task Out 人工别名 → 已应用并固定的名称 → 来源会话名 → 首条有效用户消息的临时显示**。只有缺少前三项时，才允许生成会话名称建议。临时显示不是原应用名称，详情中展示命名依据。

Codex 按稳定会话 ID 查询所选名称资料目录，读取 `session_index.jsonl` 的 `thread_name`，以及最新兼容 `state_*.sqlite` 中 `threads.name`。数据库旧格式只有 `title` 时，仅接受可与首条消息区分的单行名称，不把首条提示词直接当作会话名；需要时读取 `first_user_message` 补充命名依据。索引名称比数据库记录更新时使用索引，否则优先数据库名称。未配置、暂不可用或格式不兼容时回退已有名称及有效消息，不影响会话日志读取。名称索引本轮读取上限为 16 MB、单行 64 KB；出现读取提示时不把未找到名称视为来源已删除名称。

名称资料目录的候选来自当前用户环境或所选存储位置；只有确实存在普通 `session_index.jsonl` 或 `state_*.sqlite` 文件时才给出位置，不把符号链接当依据，发现不读取内容。界面可预填候选，但预览前必须明确列出该范围，由用户点击预览后才读取。显式选择后保存真实路径，只读该目录内允许的文件；跳过符号链接，目录被重定向后停止名称读取。授权会话日志目录不等于授权读取它的父目录。

Claude 格式读取日志中的 `custom-title` / `customTitle`，改名事件不作为新的会话活动。没有已固定名称或人工别名时，来源明确的改名可同步到 Task Out；只改名称不制造新的发起时间或最近活动。

命名解析会跳过日志中的顶层系统包装（推荐插件、应用说明、环境上下文、恢复上下文等），保留包装后的实际用户请求；正文或代码块中引用这些标签不会被误删。旧游标和记录的命名依据按版本修复，无法在有界读取中确认首条请求时保持缺失，不把后续轮次冒充首条。

无原名时，扩展仅在 `allowAI` 与独立的 `includeNaming` 都允许、所有相关连接均同意时，把首条有效用户消息与最新有效消息节选交给模型。模型提出长期主题的简短名称，最多 80 字；新会话首次自动整理或用户主动预览应用后保存到 `user.sessionName`。已归类会话的进展更新不补改名称，仍缺名时使用详情命名或主动重新整理。后续消息、再次整理、服务同步或补到原名都不覆盖它；人工别名始终优先，撤销仍核对修改版本。没有命名授权时，首条消息的临时显示不会借由标题字段发送给模型。

## 启动与本机数据

安装 Node.js 24（≥24.12.0，<25；当前验证版本为 24.12.x）后，双击 `scripts/Start Task Out.command`，或运行 `npm start`。脚本检查环境、启动独立后台进程，并复用同端口上已运行的 Task Out 服务。启动成功后可关闭终端窗口，不配置开机自启。

| 环境变量 | 用途 |
|---|---|
| `TASK_OUT_PORT` | 默认 `4518`；修改后同步更新扩展中的连接地址 |
| `TASK_OUT_DATA_DIR` | SQLite 数据目录；默认位于仓库外的用户应用数据目录 |
| `TASK_OUT_NODE` | macOS 脚本使用的 Node 可执行文件路径 |

macOS 默认数据位置是当前用户的 `~/Library/Application Support/Task Out`。其他系统采用其用户数据目录，但首版验收目标是 macOS + Chrome。数据库保存配置、游标、必要缓存和配对令牌摘要，数据库文件只允许当前用户读写；项目和人工修正另存在扩展 IndexedDB。

扩展「设置 → 管理会话来源」显示本次服务的运行状态与启动时间；已配对且服务支持时提供「停止服务」。停止会等待已接受的同步和写入完成，不撤销配对、不删除来源与缓存，也不停止原应用里的 Agent。命令行可用 `npm stop`、`npm restart`；`npm run service:foreground` 仅用于前台调试。旧版服务没有启动身份文件时不自动终止它，需先在原终端按 `Ctrl+C` 停止。

后台运行信息保存在应用数据目录的 `service-<port>.json`，权限仅当前用户可读写；其中的临时配对码在成功配对后移除，不由健康检查返回，也不进入 `service.log`。再次运行启动脚本可查看尚未消费且未过期的配对码；需要新码时运行 `npm restart`。日志不记录会话正文或模型 Key。停止命令先核对正在运行的服务身份，再向对应进程发送停止信号，拒绝使用陈旧 PID 停止未知进程。临时断连时先检查服务状态和地址，不需要删除应用数据。

## HTTP 接口与安全边界

服务只监听 `127.0.0.1`，接受对应端口的 `127.0.0.1` / `localhost` Host。首次启动显示 10 分钟有效的一次性配对码；配对后使用绑定 `chrome-extension://<extension-id>` 身份的 Bearer 令牌。重启产生新码，已配对令牌仍有效。

通常以浏览器提供的扩展 Origin 核验身份。Chrome MV3 的特权请求有时完全不带 Origin，此时扩展后台使用 `X-Task-Out-Extension: chrome.runtime.id` 声明身份，服务仍要求配对码或绑定该身份的令牌。只要 Origin 存在，就必须是合法扩展 Origin；自定义头存在时还须与之匹配。普通网页的 HTTP(S) Origin、字面量 `null`、无任何身份的请求和错误 Host 均不能访问私有数据。网页携带自定义头触发的预检同样被拒绝，不开放通配 CORS。

写入请求使用 JSON 对象，正文上限 128 KB。`/health` 可在无 Origin 的本机请求中读取，不返回连接、目录或会话信息；除配对外的私有接口需要令牌及匹配的扩展身份。

| 方法与路径 | 输入 / 返回 |
|---|---|
| `GET /health` | `{name,version,paired,instanceId,runId,state,mode,startedAt}`；不返回配对码 |
| `POST /pair` | `{code}` → `{token}`；成功后配对码失效 |
| `DELETE /v1/pair` | 撤销当前令牌 |
| `GET /v1/service` | 已配对扩展读取运行状态、运行方式、启动时间和是否可停止 |
| `POST /v1/service/stop` | `{}`；已配对扩展请求停止，先返回 `stopping` 再等待已有操作完成并退出 |
| `POST /v1/directories/select` | `{}` → `{path,cancelled}`；已配对扩展打开 macOS 目录选择器，取消正常返回；不接受路径或脚本参数 |
| `GET /v1/connectors` | `{connectors}`，包括声明、配置字段、候选目录与能力 |
| `GET /v1/connections` | `{connections}` |
| `POST /v1/discover` | `{connectorId?,roots?}` → `{candidates,diagnostics}`；显式范围最多 20 个目录，候选按真实目录去重 |
| `POST /v1/test` | 连接配置 → `{records,warnings,capabilities,summary,diagnostics,canEnable}`；最多 10 条样例，统计整个本次可读取范围，不保存配置、正文缓存或游标 |
| `POST /v1/connections` | 连接配置 → `{connection}` |
| `PATCH /v1/connections/:id` | 更新配置 → `{connection}` |
| `DELETE /v1/connections/:id` | 断开连接，保留缓存 |
| `POST /v1/sync` | `{connectionId?,dueOnly?}` → `{records,connections,errors}`；`dueOnly:true` 尊重各连接读取间隔，手动刷新可省略 |
| `GET /v1/records/:id` | 已缓存稳定 ID → `{record}`；不能传任意文件路径 |

相同数据目录保留 `instanceId`。客户端应分别展示保存失败、部分同步和离线，不根据 HTTP 成功推定实时状态。模型由扩展独立请求，服务没有模型代理或密钥接口；不能为网页演示把 CORS 改为 `*` 或取消鉴权。

候选在原 `connectorId`、`name`、`root` 等字段外提供 `displayName`、`icon`、`recognition`、`evidence`（字符串数组）与 `metadataRootSuggestions`（路径数组）。`summary` 包含 `mainCount`、`childCount`、`totalCount`、`sampleLimited`、`truncated`、`scanTruncated`、`partial`，可附实际识别出的 `identity`；只有 SDK 入口时不能据此填入某个客户端品牌。预览诊断为 `{code,message,action}`，发现诊断可另带 `root`、`connectorId`。无完整读取依据时不能把权限问题或扫描上限误报为近期无会话。

失败响应提供 `{error,code}`，保留可理解的处理动作，不回显配对码、令牌或模型 Key：

| code | 处理 |
|---|---|
| `PAIR_CODE_INVALID` / `PAIR_CODE_EXPIRED` / `PAIR_CODE_USED` | 分别提示核对当前码、重启取得新码、使用已有连接或重新取码 |
| `CONNECTION_EXPIRED` | 重新配对，已有记录与配置保留 |
| `DIRECTORY_NOT_FOUND` / `READ_PERMISSION` | 重新选择目录或检查系统访问权限，不当作空会话 |
| `UNSUPPORTED_FORMAT` | 选择对应格式及目录，或使用标准导入；不能启用 |
| `CONNECTION_EXISTS` | 使用已有连接；新增和编辑均按实际目录检查重复 |
| `NO_RECENT_SESSIONS` | 作为成功预览的诊断，可扩大时间范围或启用等待新活动 |
| `NAME_METADATA_NOT_FOUND` / `PREVIEW_INCOMPLETE` | 分别提示可跳过名称资料、或数量仅覆盖已读取部分 |
| `DIRECTORY_PICKER_UNAVAILABLE` / `DIRECTORY_PICKER_BUSY` / `DIRECTORY_PICKER_TIMEOUT` | 手填目录、完成已有选择窗口、或重新选择；取消返回成功而非错误 |

## 扩展连接器

连接器目录位于 `service/connectors/registry.mjs`。声明包含 `id`、`version`、`name`、`icon`、`configFields`、`capabilities`、`defaultRoots`，目录接口另返回可选的 `metadataRootSuggestions`，由通用界面呈现。候选位置不等于读取授权。首版 JSONL 连接器通过文件身份识别、增量聚合和来源判定提供统一记录；新格式需要实现读取适配，不是把可执行代码粘贴进配置。

新增连接器至少需要：

1. 提供发现依据、配置字段、稳定身份和时间依据；默认目录从当前用户环境生成。
2. 返回统一记录：`id`、`originId`、`connectorId`、`kind`、`source`、`title`、`sourceTitle`、`titleBasis`、`firstMessage`、`latestMessage`、`createdAt`、`createdAtBasis`、`updatedAt`、`syncedAt`、`status`、`summary`、`timeline`、`parentId`、`locator`、`capabilities`、`observations`。名称及活动时间需要有来源依据；创建时间未知用 `null`，可另给 `earliestActivityAt`。`observations` 携带连接身份与各项模型许可，不允许只选最宽松连接。
3. 分别声明历史、打开原处、实时状态等能力；未实现的能力保持关闭。
4. 用虚构数据覆盖重复同步、共享身份、截断/坏行、断连、来源冲突、时间缺失、路径范围和发送许可，再更新兼容表。

通用首页不为品牌增加分支。第三方连接器安装、自动执行下载代码、原始日志字段映射和源工具原生归档同步不在首版范围。

## 扩展内的整理与用量数据

主要类型由扩展统一约束，不由连接器新增。每条记录的 `user.tags` 仅允许空数组或七个固定类型中的一个：调研分析、需求规划、方案设计、开发实现、测试排障、文档整理、使用咨询。旧数据按明确映射收敛，无法映射的工具名、主题名等从主要类型移出；原标签完整保存在 `user.legacyTypeTags`。迁移可重复执行，不覆盖已有备份，也不改变项目和人工保护。导入与撤销同样遵守此规则。

模型调用由扩展发起，用量与价格保存在扩展 IndexedDB，本机服务不接收模型 Key、请求正文或用量账本。账本记录 Task Out 的分组、进展、命名、测试调用和每次重试；已发出但失败或取消的请求仍计入次数。缺失 usage 或必要价格保持未知，不能变成零；无升级前历史。按本地自然日保留最多 120 天汇总、最近 100 次明细，界面提供今天 / 7 天 / 30 天范围。

价格按规范化网关地址与模型名称分别设置，以每百万 token 计输入、输出、缓存输入价格，支持 CNY / USD / EUR。表单留空保留原价，首次留空未知，显式 0 有效。每次请求开始时取得价格快照，后续修改不重算历史；币种分开统计。缓存信息不完整时按普通输入价估算并标明部分估算；记录不足 24 小时不预测，之后基于近期最多 7 天日均推算未来 30 天。该估算不等同供应商账单。

## 标准导入

支持 JSON 数组、单条 JSON 对象、带 `records` 的 JSON 对象，或每行一个记录对象的 JSONL。每条记录必须有稳定 `id`；网页还需要有效的 HTTP(S) `url`。示例：

```json
{
  "id": "research-001",
  "kind": "session",
  "source": {"id": "example-agent", "label": "示例 Agent", "icon": "message"},
  "title": "比较三种任务看板方案",
  "createdAt": 1788854400000,
  "updatedAt": 1788940800000,
  "summary": "已完成方案比较，等待确认首版范围。",
  "allowAI": false,
  "includeSummary": false
}
```

日期须使用数值形式的 Unix 毫秒时间戳；ISO 日期字符串目前不解析，缺失或不支持的日期值保留未知。状态按非实时信息处理。父子会话用 `parentId` 指向同数据集的原始 `id`。单次上限 10 MB / 10000 条，失败行在预览中说明。

标准记录的 `title` 默认视为来源已提供的名称。缺名会话可明确填写空的 `sourceTitle`、`titleBasis: "first-message"`，以及 `firstMessage`、`latestMessage`；`allowAI`、`includeSummary`、`includeNaming` 均默认关闭。命名许可与近况许可独立；在允许范围内，名称可在新会话首次自动整理时补全，也可手动预览后应用，不能通过导入让模型替换已有名称。

填写稳定的数据集标识，重复导入相同数据集与 `id` 更新原记录；标题相同不是去重依据。不同数据集独立。导入不读取记录所指向的任意本地路径，不恢复浏览器绑定。

内容备份还携带项目和用户整理信息，首次导入可恢复这些内容，后续重复导入保留已有的新调整。配对凭据、模型 Key 和浏览器绑定不恢复。配置模板供新环境参考填写，不自动批量启用连接；内容备份含私人工作信息，不应提交 GitHub。`examples/` 只提供虚构样例。任意工具原始日志需要对应连接器先重建会话。
